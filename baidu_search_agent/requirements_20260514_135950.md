# 基于 LangGraph 与 Baidu MCP 的智能搜索分析 Agent

## 项目概述
本项目旨在开发一个企业级/个人级的智能搜索代理（Search Agent）。基于 **LangGraph** 框架，该 Agent 具备“查询意图修复”能力，能够针对用户模糊的搜索请求进行澄清或自动推理。
核心搜索源为 **百度搜索引擎（通过 MCP 协议接入）**，推理大脑支持 **DeepSeek** 及 **硅基流动（SiliconFlow）** 平台的高性能大模型。系统不仅能返回原始搜索结果，更能对全网信息进行深度比对、去噪与逻辑归纳，输出结构化的中文高质量总结。

## 核心功能
1.  **模糊意图识别与澄清 (Intent Clarification)**：
    *   接收自然语言输入，判断语义明确度（如 "XXX 怎么样" 是否模糊）。
    *   若模糊，自动触发追问节点（Follow-up Question）或基于知识库生成候选搜索词，避免无效搜索。
2.  **MCP 驱动的百度搜索 (Baidu Search via MCP)**：
    *   摒弃传统爬虫或封装 API 的反向对接，采用 **Model Context Protocol (MCP)** 标准工具。
    *   支持标题、摘要提取，自动过滤百度结果中的广告与非相关内容。
    *   支持多轮搜索（Multi-turn Search），若首轮结果质量低，自动触发“换词搜索”节点。
3.  **深度内容分析 (Deep Analysis)**：
    *   利用 DeepSeek 等模型的逻辑推理能力，对多个来源的网页片段进行交叉验证。
    *   生成包含 `<关键事实>`、`<争议点>`（如有）、`<结论>` 的 Markdown 结构化总结。
4.  **状态流控制 (Workflow Control)**：
    *   利用 LangGraph 的 `StateGraph` 管理搜索（Searching）-> 分析（Analyzing）-> 总结（Summarizing）的全生命周期。
    *   内置死循环阻断器（Max Retry Count），防止 Agent 在某个错误状态无限循环。

## 技术架构
- **编排引擎**：LangGraph (Python)：负责定义状态流转图，管理节点调用顺序。
- **大语言模型层 (LLM Layer)**：
    *   **首选模型**：DeepSeek-V3 (逻辑推理强)。
    *   **备选平台**：硅基流动 (SiliconFlow) API 兼容 DeepSeek 模型，提供高并发/低延迟保障。
    *   **模型路由策略**：通过配置文件支持上下文中自动或手动切换 API 端点。
- **搜索工具层 (MCP Provider)**：
    *   集成 `pylax` 或 `mcp` 客户端库，连接百度搜索引擎 MCP Server。
    *   支持断网兜底（本地模拟搜索或备用关键词搜索）。
- **服务层**：FastAPI + Uvicorn。
- **监控与日志**：LangSmith / LangFuse（记录完整思维链 Tracing），结合 Baidu Cloud Monitor。

## 实现细节

### 1. 环境配置 (`.env` 与 配置类)
需维护统一的配置管理器，屏蔽底层 LLM 差异：
```python
import os

class ModelConfig:
    def __init__(self):
        self.api_base = os.getenv("MODEL_BASE", "https://dashscope.aliyun.com" # 示例可切换
                          if os.getenv("MODE_PLATFORM") == "silicon" else "https://api.deepseek.com")
        self.api_key = os.getenv("API_KEY")
        self.model_name = os.getenv("MODEL_NAME", "deepseek-chat")
    
    def get_llm(self):
        return LLMWrapper(base=self.api_base, key=self.api_key, name=self.model_name)
```

### 2. LangGraph 状态定义 (State Schema)
定义类型化的共享状态，确保节点间数据传递安全：
```python
from typing import List, Optional
from pydantic import BaseModel, Field
from mcp import Client, SearchTool

class SearchState(BaseModel):
    session_id: str
    user_input: str
    queries: List[str] = Field(default_factory=list)
    search_results: List[dict] = Field(default_factory=list) # 来自 Baidu MCP
    history: str = "" # 用于 Context 累积的聊天历史
    analysis: Optional[str] = None # 中间推理结果
    final_answer: Optional[str] = None
    status: str = "INITIAL" # INITIAL, SEARCHING, ANALYZING, DONE, FAILED
```

### 3. 关键节点 (Nodes) 逻辑实现
- **Node: `update_mcp_search_request` (MCP 搜索节点)**
    - 输入：`SearchState`
    - 操作：调用 LangGraph 自带的 MCP 工具组件 `Client` 执行 `baidu_search_tool("当前查询")`。
    - 错误处理：若 MCP 返回 CodecError，触发 `fallback_keyword` 逻辑。
    - 输出：返回清洗后的 Top 5 搜索结果（含 Title, URL, Snippet）。
- **Node: `intent_parser` (意图解析节点)**
    - 模型：引入 DeepSeek 0.5 Context。
    - 逻辑：
        1.  判断 `queries[-1]` 是否包含明确实体。
        2.  若包含 `?`、名词不完整、或逻辑矛盾（如 "搜索苹果和香蕉" 但只有一键读取能力强）。
        3.  输出 `ToolRef`（追问规则）或 `NextTool`（直接搜索）。
- **Node: `synthesize_summary` (总结生成节点)**
    - 逻辑：
        1.  将 `search_results` 注入 Prompt 作为 `Input Info`。
        2.  调用 LLM 执行以下指令："基于以下搜索结果，忽略不确定性来源，总结出来龙去脉，必须引用原文链接..."
        3.  输出格式为 Markdown，并附加源链接列表。

### 4. 提示词工程 (Prompt Engineering)
```markdown
# Role: 高级检索分析专家
# Task: 利用百度搜索结果生成高质量中文总结
# Constraints:
1. 严禁编造数据，若结果不足至少 3 条来源，如实告知信息缺失。
2. 输出结构：[核心结论] -> [依据来源] -> [详细分析]。
3. 语言：简体中文。
# Data Format:
<search_results>
{{ search_results | join("...") }}
</search_results>
```

## 输入输出规范

### 1. 接口定义
- **路径**：`POST /api/v1/search`
- **鉴权**：API Key Header (`Authorization: Bearer <api_key>`)
- **请求体 (JSON)**：
    ```json
    {
      "query": "硅基流动与deepseek 平台对比 2024",
      "model_choice": "silicon", // "deepseek" or "silicon"
      "max_retries": 3, // 搜索失败重试次数
      "wait_time": 5  // LLM 分析超时秒
    }
    ```
- **响应体 (JSON)**：
    ```json
    {
      "code": 200,
      "message": "Success",
      "data": {
        "answer": "## 对比总结\n1. **性能对比**...\n\n[来源] 1. silicon-ai.com...",
        "sources": [
          "https://tech.siliconflow.io/demo-1",
          "https://blog.deepseek.com/analysis-2"
        ],
        "metrics": {
          "total_searches": 2,
          "models_used": ["deepseek-chat", "silicon-flow-v3"]
        }
      }
    }
    ```

### 2. 流式响应 (SSE/Streaming)
- 支持 `Accept: text/event-stream`。
- 在 `synthesize_summary` 节点完成前，通过 `SseIterator` 分块返回 Markdown 内容，降低首字延迟（TTFT）。
- 集成 LangChain `StreamOutput` 或自定义 FastAPI SSE 处理。

## 特殊要求
1.  **MCP 协议适配**：
    - 需开发或引用开源 MCP Server 支持百度搜索功能。若暂无标准 Server，需在 FastAPI 内部构建符合 MCP JSON-RPC 规范的中间层并注册为 Tool。
2.  **模型切换能力**：
    - 支持运行配置时热切换模型（在冷启动阶段自动检测硅基流动 SDK），无需重启服务。
    - 日志中需区分 `ModelProvider: DeepSeek` 或 `SiliconFlow`。
3.  **防幻觉与安全**：
    - 在 Prompt 中强制要求 Model 输出引用格式 `[^1]`。
    - 针对百度搜索结果，需使用正则过滤明显营销广告域名的结果（如 `.ads.yahoo.com` 等误伤，但针对百度国内 URL 特征加白名单）。
4.  **成本优化**：
    - 设定 Token 消耗阈值，超过阈值自动降级为精简版模型（如 DeepSeek-R1-Distill-Lite）。
    - Baidu MCP 搜索成本应计入配额，单查询搜索次数需记录在本地 Redis 缓存中。
5.  **可观测性**：
    - 必须记录 Graph 的 `Step Logs`。
    - 若 `analyze` 节点输出置信度较低，必须标记在 Response 中，提示用户“此回答基于有限网络信息”。
